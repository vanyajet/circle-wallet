# ADR-0001: Omnibus — treasury, deposit-адреса и sweep

**Статус:** Accepted

## Контекст
У каждого пользователя должен быть свой адрес для пополнения. Вывод возможен в пределах баланса.
Балансы ведёт само приложение. Есть две классические модели хранения средств.

## Решение
**Omnibus.**
- Каждому пользователю выдаётся deposit wallet (SCA, `refId = userId`).
- После депозита в статусе `COMPLETE` средства сметаются (sweep) на общий **treasury** (hot wallet).
- Все выводы идут из treasury, принадлежность средств определяет только леджер.
- Treasury можно пополнить собственными средствами сервиса (**house float**, equity-счёт `HOUSE`),
  чтобы выводы не ждали sweep.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Кошелёк на пользователя** (вывод из своего кошелька) | Проще; on-chain баланс кошелька = баланс пользователя; нет sweep | Ликвидность раздроблена: вывод упирается в баланс одного адреса. Внутренние переводы, комиссии и пулинг невозможны без on-chain движения. Так не работают биржи и кастодиальные кошельки |
| **Omnibus + sweep** (выбрано) | Как в реальных кастодиальных системах: единая ликвидность, контроль в одной точке, готовность к cold/hot разделению | Нужны sweep, классификация входящих на treasury, учёт ликвидности. Сложнее леджер (custody vs обязательства) |
| Omnibus с forwarder-контрактами (CREATE2, авто-форвард) | Нет отдельного sweep-процесса | Собственные смарт-контракты, вне возможностей Circle dev-controlled wallets |
| Memo/tag-депозиты на один адрес | Один адрес на всех | В EVM нет нативного memo; противоречит ТЗ («у каждого пользователя свой адрес») |

## Последствия
- Sweep проводится по **своей outbound-транзакции**. Входящее на treasury классифицируется
  (`SWEEP` / `HOUSE_FUNDING` / `UNCLASSIFIED`), при сомнении — в безопасную сторону.
- Вывод проверяет **ликвидность treasury** (custody − выводы в пути). Если её не хватает, вывод
  ждёт (`awaiting_liquidity`), а не падает.
- Sweep делается только после `COMPLETE` и только выше порога `SWEEP_MIN_AMOUNT`, чтобы не тратить
  газ на мелочь.
- Treasury — единственная точка исходящих транзакций, а значит и узкое место по throughput.
  В проде нужен пул hot wallets (future work).
