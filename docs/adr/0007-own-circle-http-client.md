# ADR-0007: Собственный HTTP-клиент Circle вместо SDK

**Статус:** Accepted

## Контекст
Circle — REST API. Каждый мутирующий запрос требует Bearer API key, одноразового
`entitySecretCiphertext` (RSA-OAEP-SHA256 на публичном ключе Circle) и `idempotencyKey`.
Адрес API берётся из `CIRCLE_BASE_URL`; возможно, приложение запустят против мока.
Официальный SDK — `@circle-fin/developer-controlled-wallets` (10.8.1).

## Решение
Тонкий клиент на `fetch` за интерфейсом `CircleGateway`. Доменный код зависит от интерфейса,
тесты используют `FakeCircleGateway`. Что делает клиент:
- строит URL строго от `CIRCLE_BASE_URL`;
- генерирует ciphertext на каждый запрос, публичный ключ кеширует;
- требует `idempotencyKey` явно;
- ставит таймауты через `AbortSignal`;
- валидирует ответы zod-схемами;
- классифицирует ошибки (unknown outcome / retryable / config / definitive);
- поддерживает фильтр `refId` и пагинацию от base URL.

## Почему не SDK (найдено при чтении исходников 10.8.1)
- Нет таймаутов и ретраев (глобальный axios).
- Если не передать `idempotencyKey`, SDK молча подставляет `randomUUID()`, и ретрай создаёт второй перевод.
- `listTransactions` не пробрасывает фильтр `refId`, который нужен для восстановления потерянного ответа.
- Хелпер `getTransaction({waitForState})` считает `STUCK` терминальным, хотя это не так.
- Завершающий `/` в `baseUrl` даёт `//v2/...`.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| SDK напрямую | Меньше кода, официальный | См. выше; домен привязан к SDK |
| SDK за интерфейсом | Официальный код за абстракцией | Те же недостатки внутри; обходы смешивают SDK и сырой HTTP |
| **Свой клиент за интерфейсом** (выбрано) | Полный контроль надёжности; явное поведение на моке; zod ловит расхождения контракта | Больше кода; изменения API отслеживаем сами |

## Последствия
- Основной поток использует минимальный контракт: create wallet, transfer, get transaction,
  notification public key. Остальное (list по `refId`, balances) деградирует мягко.
- Скрипт регистрации entity secret вызывает `POST /v1/w3s/config/entity/entitySecret`. Этого
  эндпоинта нет в публичной OpenAPI, путь взят из исходников SDK.
